# ShifPita MVP 要件定義書

## 1. プロジェクト概要

### 1.1. アプリケーション名
ShifPita MVP (シフピタ)

### 1.2. 目的
特定施設の複雑な勤務条件（ハード制約・ソフト制約）に対応した勤務表を自動生成するWebアプリケーションを開発する。**管理者と従業員がそれぞれ専用のダッシュボードを持ち、希望休の申請からシフト作成、履歴の確認までを一貫してオンラインで管理できる環境を提供する。** これにより、手動作成の負担を抜本的に解消し、従業員の公平性や希望を最大限に尊重した質の高い勤務表を作成する。

### 1.3. 基本方針
本アプリケーションは、**ユーザー認証機能を備えた多機能Webアプリケーション**として開発する。**管理者は従業員アカウントを管理し、従業員は自身の希望休を申請できる。** これらの情報はデータベースで永続的に管理され、シフト作成時の制約条件として利用される。生成された勤務表はPDF形式で出力できる。

## 2. 機能要件

### 2.1. 従業員情報入力機能
- **期間設定:** 勤務表を作成する対象月を指定できる。
- **従業員リスト入力:** 以下の属性を持つ従業員のリストを入力できる。
  - **名前:** 従業員の氏名
- **役割:** `介護員`, `パート1`, `パート2`, `パート3`, `パート4`,`責任者`, `サポート` から選択。役割に応じて、後述の制約が自動的に適用される。

### 2.2. 勤務希望・イベント入力機能
- **希望休入力:** 従業員ごとに、希望する休日を日付で厳守指定できる。
- **特別日設定:** 「通院日」など、通常とは異なる人員配置が必要な日を特定し、その日に必要な追加人数（例: +1人）を設定できる。

### 2.3. シフト自動作成機能
入力された情報に基づき、以下のハード制約・ソフト制約を考慮した最適なシフトを自動で生成する。

#### 2.3.1. ハード制約（必須遵守ルール）
- **人員配置(重要度：高):**
    - **平日・土曜:** 7-16時(4人以上), 16-20時(3人以上), 20-翌7時(2人以上)
    - **日曜:** 7-16時(4人以上), 16-20時(4人以上), 20-翌7時(2人以上)
    - ※夜勤（20-翌7時）は、日付をまたぐ両方の時間帯で必要人数を満たすこと。
    - ※「通院日」として設定された日は、上記人数に指定された追加人数を加算する。
- **連続勤務（重要度：高）:**
    - 遅番・夜勤の連続は最大4日まで。
    - 全ての勤務の連続日数は最大5日まで。
- **夜勤規則（重要度：高）:**
    - 夜勤の翌日は「夜勤」または「明」とする。
    - 「明」の翌日は必ず「休」とする。
- **月間勤務日数（重要度：中）:**
    - `介護員`の役割: 月21日勤務を厳守。
    - `パート`の役割: 希望休以外は勤務を厳守。
- **役割別制約（重要度：高）:**
    - **勤務パターン（シフト区分）:**
        - `パート4`以外: 早1, 早2, 日1, 日2, 遅1, 遅2, 夜1, 夜2
        - `パート4`: 1, 2, 3, 4, 5, 6, 7, 8
    - `パート2`, `パート3`: 夜勤シフト（夜1, 夜2）の割り当て不可。
- **希望休（重要度：中）:**
    - 全従業員の希望休を厳守する。

#### 2.3.2. ソフト制約（最適化目標・重み付け）
- **高 (High):**
    - `介護員`の夜勤回数を月10回に可能な限り近づける。
- **中 (Medium):**
    - `パート1`は夜勤を優先的に割り当てる。
    - `パート2`は遅番を優先的に割り当てる。
    - `パート3`は遅番とそれ以外の勤務を同程度の頻度で割り当てる。
    - 全員の連続勤務日数が、可能な限り短くなるように調整する。
- **低 (Low):**
    - `責任者`と`サポート`は早番を優先的に割り当て、かつ可能な限り同日に勤務しないようにする。

### 2.4. 結果出力機能
- 自動作成された勤務表を**PDF形式**でダウンロードできる。
- PDFは日付と従業員を軸にしたカレンダー形式で、シフト（例: 早, 遅, 夜, 明, 休）が一目でわかるデザインとする。

### 2.5. Webアプリケーション機能（ユーザー認証・ダッシュボード）
- **希望休申請:** 従業員はWebアプリケーション上で希望休を申請できる。申請された希望休はシフト作成時の制約条件として自動的に反映される。
- **ダッシュボード:** 
    - **従業員用ダッシュボード:** ログイン後、希望休の申請、確定したシフトの確認、自身のユーザー情報（パスワード・メールアドレス）の変更が可能。
    - **管理者用ダッシュボード:** ログイン後、従業員の追加、シフト自動作成、過去のシフト作成履歴の確認、自身のユーザー情報の変更が可能。
- **ユーザー登録:**
    - 従業員のユーザー登録は管理者のみが行える。
    - アプリ導入時の初回に限り、管理者アカウントを1名のみ登録できる。
- **認証情報:**
    - ユーザーID（半角英数字６文字以上）とパスワード（半角数字４文字）を必須とする。
    - メールアドレスの登録は任意とする。
- **通知機能:**
    - メールアドレスが登録されている場合、従業員はシフト作成完了通知を受け取れる。
    - メールアドレスが登録されている場合、管理者は従業員からの希望休申請通知を受け取れる。

### 2.6. 範囲外の機能
- 生成された勤務表の手動修正機能

## 3. 非機能要件
(従来通り)
- **パフォーマンス:** 従業員20名、1ヶ月分のシフト作成が30秒以内に完了する。
- **セキュリティ:** 通信のHTTPS暗号化、パスワードのハッシュ化、データベースによるデータ永続化。
- **UIの応答性:** 入力操作がスムーズに反映されること。
